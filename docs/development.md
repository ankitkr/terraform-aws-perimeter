# Development

## Layout

```
*.tf                     the main module
modules/member/          the member submodule; events.json lists the tripwire events per source
lambda/perimeter/        the functions (Python 3.14, boto3 only), packaged by Terraform
  app.py                 handlers: planner, scanner, judge, tripwire
  model.py               endpoints, paths, observations, expectations, verdicts, alerts, config
  internet.py            what counts as the internet; address-set arithmetic
  paths.py               why a port is reachable: security groups, NACLs, routes, load balancers
  classify.py            verdicts per port and per endpoint; expectation matching
  diff.py                alerts from the stored and current verdicts; baseline suggestion;
                         the inventory document
  plan.py                what a run probes, and the scanner batches
  scanner.py             the TCP connect scan and HTTP probes
  ports.py               port profiles, generated by tools/gen_ports.py
  tripwire.py            judgments of CloudTrail events
  inventory.py           listing endpoints through boto3 clients; the ownership re-check
  aws.py                 member sessions, DynamoDB, S3, SNS, Step Functions
deploy/, deploy/member/  clone-and-apply stacks
examples/                module usage
tools/gen_ports.py       regenerates ports.py from Nmap's nmap-services
tests/                   pytest; tests/terraform: terraform/tofu test with a mocked provider
```

`model.py`, `internet.py`, `paths.py`, `classify.py`, `diff.py`, `plan.py` and `tripwire.py`
do no I/O. `scanner.py` does network I/O only. `inventory.py` and `aws.py` hold every AWS call.

## Tests

```sh
python3.14 -m venv .venv
.venv/bin/pip install -r tests/requirements.txt
.venv/bin/pytest -q tests
```

- `test_paths.py` builds fixture VPCs: NACL order and denies, main and explicit route tables,
  NAT, a more specific route, prefix lists, NLB with and without security groups and client-IP
  preservation.
- `test_tripwire.py` judges every sample in `tests/fixtures/cloudtrail.json` (EventBridge's
  shape of real CloudTrail events), and checks that `modules/member/events.json` lists exactly
  the events `tripwire.py` judges.
- `test_scanner.py` scans local sockets (open, closed, filtered) and checks the rate cap, the
  concurrency cap, and refusals.
- `test_inventory.py` and `test_aws.py` use moto for EC2, DynamoDB and S3, and fakes with the
  real response shapes for the rest. `test_app.py` runs planner, judge and tripwire end to end
  over moto.

Terraform:

```sh
terraform fmt -check -recursive
terraform init -backend=false && terraform validate
terraform init -backend=false -test-directory=tests/terraform
terraform test -test-directory=tests/terraform
```

`tofu` works the same way. CI also validates `modules/member`, `deploy`, `deploy/member` and
the examples, with their GitHub sources rewritten to the checkout.

## Adding a tripwire event

1. Add a judgment and an `EVENTS` entry in `lambda/perimeter/tripwire.py`.
2. Add the name under its source in `modules/member/events.json`.
3. Add a sample event to `tests/fixtures/cloudtrail.json` and its expected outcome to `CASES`
   in `tests/test_tripwire.py`.

## Adding an endpoint kind

Add the kind to `Kind` in `model.py`, a listing function to `inventory.py` called from
`discover_region` or `discover_global`, the read actions to the member role in
`modules/member/main.tf`, and a fake-based test in `tests/test_inventory.py`.
